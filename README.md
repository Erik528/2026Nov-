# Ad Atelier · Meta 广告多尺寸工作台

上传分层 PSD → 视觉识别文字/Logo/背景与主体 → 背景四周各扩展 50% 并缓存 → AI 排版与目标预览视觉复核 → 在画布调整 → 分别下载最新 JPG / 分层 PSD。原有 JPG 拆分流程仍可用。

**尺寸按钮只生成预览，不自动下载。** 未命名智能对象也会按其渲染内容识别，不只依据图层名称。文字与 Logo 受安全区约束，照片、渐变和装饰可出血；程序检查坐标与实际像素遮挡，不把未知图层直接判为安全。

## 本地启动

Python 3.11+（实测 3.12），无需 Node 构建、数据库或 GPU。

Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS：

```bash
bash scripts/install.sh
# 首次安装时复制 .env.example 为 .env 并填写密钥；保留已有配置
bash scripts/start.sh
```

本机浏览器访问 `http://127.0.0.1:8000`。云 onboarding 不支持 loopback 预览链接。已有云任务直接使用 `/workspace/2026Nov-` checkout，不创建 worktree。

更新时保留 `.env` 与 `data/`，覆盖源代码后停止/重启服务，浏览器 Ctrl+F5 刷新。未改变运行依赖，不必为模型配置重装软件。

## 模型与配置

```env
AD_OPENAI_API_KEY=在本机或环境设置中安全填写
AD_OPENAI_BASE_URL=https://api.openai.com/v1
AD_VISION_MODEL=gpt-4.1
AD_LAYOUT_MODEL=gpt-6.1-terra
AD_IMAGE_MODEL=gpt-image-2.5-sunburst
AD_DATA_DIR=./data
```

- `AD_LAYOUT_MODEL`：PSD 图层视觉分类、主体定位、构图及实际目标预览的视觉复核；默认 `gpt-6.1-terra`。当前云凭据已真实验证其 JSON、图像输入与四尺寸构图能力；其他账户仍需相应模型权限。可换成账户可用、支持图片与 JSON Chat Completions 的模型。
- `AD_IMAGE_MODEL`：背景补全/扩图。默认 `gpt-image-2.5-sunburst`；`gpt-image-1` 已停用，旧 `.env` 显式值需更新。
- `AD_VISION_MODEL`：保留用于原 JPG 分割识别。
- `AD_OPENAI_API_KEY` 优先于 `OPENAI_API_KEY`；进程环境变量优先于 `.env`。更改后重启服务。密钥不写入源代码、日志或导出文件。
- 网络需允许 `api.openai.com`；安装需 PyPI。云草稿已声明 secret 需求与 API 域名，草稿保存不等于运行注入、发布成功或网页上线。

API 请求计费与 ChatGPT 订阅无关。PSD 首次准备通常 **1 次视觉分类 + 1 次图像扩图**；每个新尺寸 **1 次构图 + 1 次实际预览视觉复核**，均缓存。重复切换、拖动、缩放、反白与下载不重复扩图。变更背景角色需为新背景准备/缓存扩图；仅修改前景角色不重做同一背景。请求超时不自动重试，避免隐式重复计费，完成检查点保留供显式继续。

## PSD 流程与背景保护

1. 上传 RGB / 8 位标准 PSD（≤100 MB；短边 ≥256、长边 ≤6000、≤2400 万像素）。支持 2–60 个可见顶层单元，总层数 ≤500、渲染单元总像素 ≤6000 万。
2. 服务自动解析顶层图层/组，生成各层透明 PNG、原始合成和图层联系表，视觉模型读取真实图像及元数据，识别未命名文字、品牌标志与主体。原生 type 层始终按文字保护；不能仅因名称模糊就把标题当普通图像。
3. 背景取**独立背景层的完整范围**，包括原 PSD 画布外的左右像素，不先裁成 PSD 画布。对干净背景上下左右各扩 50%，工作图从 W×H 变为 2W×2H，原图居中。扩图后程序强制恢复原中央像素，结果缓存，所有目标尺寸共用。
4. 大图 API 工作背景长边最多 1600 px；扩图为该工作背景的两倍。原始背景图层仍以独立栅格内容参与最终导出，精确目标画布不受工作图大小影响。
5. 目标画幅使用九分区背景映射：原照片中央部分**完整、等比、位于画面内**；只有生成的周边可独立适配目标长宽比，避免粗暴 cover 切掉原照片。检测到的主体尽量移入中心区域；必要时减小原照片占比，使用更多生成边缘。极端比例下周边可能伸展，需要人工审核；并非保证任何照片都能自动得到理想构图。
6. 选择尺寸生成 AI 初稿，程序先校验并约束文字/Logo 坐标，再把**实际渲染预览及安全区**交给模型视觉复核，改善标题尺寸、对比度、渐变矩形边缘及遮挡。最终仍经程序检查。失败时明确显示本地几何方案/错误，不伪装 AI 成功。
7. 右侧预览中点击元素选中；拖动移动、拖右下角手柄等比缩放、滚轮或 ± 按钮缩放；“反白”将选中图层 RGB 变为白色并保留 alpha，可恢复原色。文字/Logo 越界或真实像素相互遮挡会提示并禁用下载。图像和白色渐变出血不拦截。
8. 预览下方分别点“下载 JPG”“下载 PSD”。下载请求携带当前坐标、缩放、反白与背景参数，服务**重新渲染当前状态**，不直接下载旧预览缓存。安全区遮罩、选择框、手柄不进入文件。

图层角色可人工修正：背景、文字、Logo、图像/渐变、装饰。保存角色后更新当前构图；需要新背景时明确恢复准备步骤。没有 API 密钥、视觉识别未完成或扩图失败时，不将 PSD 标为准备完成或全安全。可配置后“继续处理（复用缓存）”。

## JPG 路径

JPG/JPEG ≤20 MB，短边 ≥256、长边 ≤6000、≤2400 万像素，按内容检查格式并校正 EXIF。真实 API 识别元素、补全背景，本地差分遮罩保留原 JPG 的文字/图案 RGB；每个 JPG 扩图一次。人工审核后选尺寸预览、调整与分别下载 JPG/PSD。

JPG 的文字/图案是合并栅格层；安全区检查文字层和识别记录中的 Logo 区域，不限制整个照片层。未识别或烘焙在图片中的文字/Logo 仍需人工审核。复杂抗锯齿、阴影、透明物体、相互遮挡可能产生孔洞或边缘光晕；这一路径不能保证无损拆分。

## PSD 导出、保留内容与限制

- 动态数量的真实独立栅格图层，包括 Canvas、AI 生成的背景扩展层、原背景单元和各前景单元，保留源顶层名称与顺序；真实透明通道，不是扁平图片改扩展名。
- **原生文字、智能对象、矢量及组内部结构渲染为栅格单元**，不保留它们的 Photoshop 原生编辑属性。原始文件原样保留为 `source.psd`；隐藏层保留在源文件和元数据，不参与本次 resize。
- 顶层剪贴、非普通混合、调整层及重建偏差过大的文件会拒绝并提示整理/编组/栅格化；不支持 PSB、CMYK、16/32 位或纯扁平 PSD。复合单元中烘焙的文案无法单独移动，建议在 Photoshop 分成独立顶层层/组。
- 每次 PSD 导出重新打开文件，验证尺寸、层数、顺序、可见性、坐标、逐像素 RGBA、重新合成，并由 Pillow 独立读取内嵌合成。没有在当前云机的 Adobe Photoshop 软件中实际打开。
- 统一安全区只读取 `app/sizes.json`：1080×1080 `[100,100,980,980]`；1080×1350 `[0,250,1080,1100]`；1080×1920 `[65,268,1015,1255]`；1200×628 `[120,60,1080,570]`。
- 本地单进程原型，不启用多个 Uvicorn worker。上传/检查点/布局/导出保存在忽略的 `data/`，没有多人权限、取消上游调用或自动清理。只绑定本机；现场广告效果与源 PSD 需用户审核。

## 验证与诊断

```bash
.venv/bin/python -m pytest -q
# 已有本地服务、Playwright 和 /usr/bin/chromium：
.venv/bin/python tests/browser_smart_preview.py
.venv/bin/python tests/browser_check.py
```

离线测试全局移除真实 API 凭据，避免误计费。浏览器编辑器测试明确使用已知本地几何背景/图层，不将这些夹具称为真实 AI 生成结果。另已用公开 OpenCV 照片制作实际分层 PSD，通过真实 API 验证未命名标题/品牌分类、一次四周扩图、四种尺寸构图与视觉复核、JPG 和分层 PSD。见 `VALIDATION.md`；用户截图对应原始 PSD 尚未提供，未宣称已验收该设计。

在**启动服务所用的同一 Python 环境**执行安全诊断（不打印密钥）：

```powershell
python scripts/check_api.py
python scripts/check_api.py --probe
python scripts/check_api.py --layout-probe
```

第一条不访问 API；后两条分别向视觉/构图模型发送微小真实请求，可能产生少量费用。HTTP 429 的 `insufficient_quota` 指 API 项目计费/额度，`rate_limit_exceeded` 指模型速率；有余额仍可能触发 RPM/TPM/IPM。HTTP 400 的模型、遮罩、组织验证或内容审核会分别提示；保留 Request ID 便于排查，不回显原始响应正文或密钥。
